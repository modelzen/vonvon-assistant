# Vonvon Bot 问题答疑

本 Skill 负责基于**真实文档与源码证据**准确回答 Vonvon Bot 的使用、配置与架构问题，不靠猜测编造设置项或命令，并在答疑后主动引导用户走好下一步。

## 第零步：初始化闸门（必检，不可跳过）

开始回答前，必须先检查 `workspace/setup-state.json` 是否存在：
- **如果不存在**：停止直接答疑，立即转入 `vonvon-setup`——在同一轮里先简短承接用户问题、一口气做完只读体检并给出 A / B 档位选项，初始化完立即无缝回到本题作答。仅在用户明确回复「本次先跳过」时，才退化为查官网文档作答。
- **如果已存在**：读取其中的 `repoPath`（默认 `workspace/vonvon-bot`），继续第一步。

## 第一步：确定资料来源

1. 从 `workspace/setup-state.json` 获取本地 `vonvon-bot` 源码路径（默认 `workspace/vonvon-bot`）。
2. **优先查本地源码与文档**：
   - 使用与入门：`README.md`、`docs/server-install.md`、`docs/windows-cli.md`、`CONTRIBUTING.md`
   - 产品规则与功能细节：`docs/product.md`（例如 3.2 Bot 模型、3.4 智能/规则模式、3.5 会话与上下文、3.6 角色/记忆/Skill/MCP、3.7 聊天里改设置、3.8 卡片与权限、3.14 远程连接）
   - 架构与安全边界：`docs/architecture.md`
   - 当文档表述有歧义或可能滞后时，**直接核对实现源码**（如 `packages/daemon/src/`、`packages/protocol/src/`、`packages/ui/src/`、`packages/desktop/src/`），以实际代码为准。
3. **仅在用户明确跳过初始化且本地无源码时**：可联网查阅官网文档（`https://vonvon.cc/docs/`、`https://vonvon.cc/docs/troubleshooting/`、`https://vonvon.cc/get/`、`https://vonvon.cc/changelog/`）作答，并标明未对照本地源码。

## 第二步：区分正式版与未发布改动

- 用户本机跑的通常是正式版（对应 `main` 或发布 tag）。
- 默认以 `main` 的行为为准；若核对到某项能力或修复仅存在于上游 `dev` 分支尚未发版，必须**明确标明「当前正式版暂不支持，已在 `dev` 分支合入，将在后续版本发布」**，避免误导用户去寻找不存在的按钮或命令。

## 第三步：组织高质量回答

回答要直接、可执行、有依据：

1. **先给结论**：1～2 句话直接回答“能不能 / 怎么配 / 为什么”。
2. **再给准确操作路径**：
   - 桌面端/网页端：写清实际页面与设置项名称；
   - 命令行：给出经过源码核实的真实 `vonvon` 命令（不编造参数）；
   - 管理员私聊：提醒可在私聊里直接用自然语言让 Bot 调配置（`vonvon-config`）。
3. **点出关键边界或常见误区**（如果相关）：
   - 权限档差异：`只读` 默认不联网、`工作区可写` 开网但受沙箱和配置保护、`完全访问` 等价于本机主人；
   - 群与私聊差异：群里不能改设置，只能在客户端、CLI 或管理员私聊里改；
   - Skill 发现路径：Codex 读 `.agents/skills`，Claude 读 `.claude/skills`；
   - 多 Bot 协作：同群多 Bot 互通需要都开启「智能」模式并具备相应飞书权限。

## 第四步：主动引导下一步（不要冷场，让用户顺着点头即可）

根据本次答疑落点，结尾给出 **1～2 个简短可直接回复的下一步选项**：

- **对照源码后发现并确认属于 Vonvon Bot 的代码 Bug**（非既定设计、非 `dev` 已修复、非安全漏洞）：
  - **绝不要止步于“解释代码为什么有这个 Bug”**！明确指出这是已确认的代码缺陷，并主动引导：
    > 「这已经确认是代码缺陷，建议提交到 GitHub 跟踪修复。回复 **帮我反馈上去**，我就先查重并帮你整理一份带图脱敏的 Issue（或复现评论）预览；如果暂时不需要，回 **先不用** 即可。」
- **问题看起来像本地报错、配置未生效或环境异常**：
  - 主动引导：「这看起来像本机运行异常，回复 **帮我排查**，我先只读检查一下你的本机状态和日志。」
- **和用户讨论出了明确的新功能需求或体验优化方案**：
  - 主动引导：「这个思路已经很清楚了，要不要我帮你把刚才聊的方案整理成一份完整的功能建议发到 GitHub？回复 **帮我整理成 Issue** 就行。」
- **用户主动问怎么自己写代码提 PR**：
  - 友好说明本助手专注答疑、排错与高质量反馈，附上 `modelzen/vonvon-bot` 的 `CONTRIBUTING.md` 链接（提醒从 `dev` 分支拉改动并向 `dev` 提 PR）。
